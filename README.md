## Flujo de trabajo Git
En este proyecto hemos aplicado el modelo **GitFlow** para organizar el desarrollo:

*   **Rama `develop`**: Es nuestra rama de integración. Aquí unimos todas las funcionalidades terminadas antes de subirlas a la rama principal (`main`).
*   **Ramas `feature/`**: Utilizamos ramas como `feature/readme-base` y `feature/documentacion-extra` para trabajar en tareas específicas sin afectar el código estable.
*   **Rama `release/v1.0.0`**: Se creó para preparar el lanzamiento de la primera versión, permitiendo hacer ajustes finales de documentación.
*   **Rama `hotfix/readme-typo`**: La usamos para corregir rápidamente un error ortográfico en el README detectado después del lanzamiento, sin detener el flujo de trabajo normal.
